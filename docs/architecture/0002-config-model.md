# 0002 — Модель конфига: Nix ↔ GUI ↔ live-apply

- **Статус:** согласовано (этап 2 из 7), 2026-11-17
- **Предыдущий:** `0001-foundations.md` · **Следующий:** `0003-compositor.md`
- **Решения этапа:** свободный attrset в Nix + рантайм-валидация по схеме; детект конфликтов при коммите с явным выбором; автоген форм из схемы + ручные страницы для визуального; секреты в Secret Service; **rebuild из GUI не запускается** — только запись + напоминание.

## 1. Четыре слоя

| Слой | Файл | Кто пишет | Роль |
|---|---|---|---|
| L0 defaults | `share/shell/00-defaults.toml` (store) | никто | эталон и документация |
| L1 nix | `~/.config/shell/10-nix.toml` (store) | Nix-модуль | настройки в git |
| L2 generated | `~/.config/shell/20-generated.toml` (store) | `shellctl config commit` → файл в `~/dotfiles` | результат GUI-коммитов |
| L3 session | `~/.local/state/shell/session.toml` | GUI в рантайме | живое, ещё не сохранённое |

Приоритет: **L3 > L2 > L1 > L0**, кроме ключей из `locked`.
Дополнительно поддерживается `~/.config/shell/90-local.toml` (ручной drop-in вне Nix, для экспериментов) и `--config-dir` для тестов/профилей. Слияние по имени файла в алфавитном порядке.

### Замки

```nix
programs.shell = {
  settings = { bar.position = "top"; };
  locked = [ "bar.position" ];   # GUI: поле серое + тултип «закреплено в Nix»
};
```
Закреплённый ключ не редактируется в GUI и не попадает в L2.

## 2. Схема — единственный источник правды

- Типы в `shell-config` (Rust): `serde` + `schemars`. На каждый ключ метаданные: `doc`, `since`, `merge`, `requires_restart`, `secret`, `enum`.
- Экспорт: JSON Schema → потребители: валидатор загрузки, Nix-модуль (опциональная проверка), GUI (формы).
- `merge` для списков: `replace` (по умолчанию), `append` (например `bar.widgets`), `union` (`theme.templates.targets`).

### Nix-модуль

`settings` — свободный attrset; типизированных options на 300+ ключей нет (второй источник правды, который всегда отстаёт). Валидация — при загрузке в шелле, с точным путём ошибки:

```
bar.widgets[3].name: unknown variant `weatherr`, expected one of [...]
20-generated.toml:41: bar.position must be one of "top"|"bottom"|"left"|"right"
```

## 3. Live-apply

1. GUI собирает изменения → **одна транзакция** L3.
2. Валидация всей транзакции (схема + семантика: например, виджет не дублируется в одной зоне).
3. Граф зависимостей ключей → план действий: `reload:theme`, `relayout:bar`, `restart:shell-ui` (шрифты, скейл), `reconnect:compositor`.
4. Атомарное применение; ошибка → **откат всей транзакции** (полу-применённых состояний не бывает).
5. UI честно сообщает: «применено» / «применится после перезапуска `shell-ui`».
6. `shellctl config show --origins` — значение и слой-источник по каждому ключу (аналог `git config --show-origin`).

## 4. Проекция в Nix (цикл коммита)

```
GUI (L3) ──commit──► ~/dotfiles/<shell-module>/settings.generated.nix
                       ├─ nixfmt (форматтер вашего flake)
                       ├─ nix-instantiate --parse (синтаксис гарантирован)
                       └─ git diff --stat → показать в UI
                       │
              [шелл показывает команду] nh os switch ~/dotfiles
              (сам rebuild из GUI НЕ запускается)
                       │
          rebuild → новый store-TOML → L3 очищается
```

- Generated-файл живёт **в `~/dotfiles`** (там, что пересобирается и уходит в auto-upgrade); `~/shell` — только код.
- Формат файла детерминирован (сортировка ключей, стабильный вывод, без логики) → `git diff` минимальный.
- Machine-owned: перегенерируется целиком, править руками не нужно и не надо.

### Конфликты (ключ задан и в Nix, и в GUI)

При `commit` шелл находит пересечение и предлагает выбор:

1. **Закрепить в Nix** → ключ уходит в `locked`, из L2 удаляется;
2. **Удалить из generated** → выигрывает ручной Nix;
3. **Перезаписать ручное** → правка уходит в человеческий файл (шелл показывает готовый фрагмент, вставка — ваша).

## 5. Миграции

- `schema_version` в generated-файле; на каждый ключ `since`.
- Цепочка переименований применяется при загрузке любого слоя, лог с `file:line`.
- Deprecated-ключи работают, но помечаются бейджем; `commit` умеет переписать их в новый вид.
- Правило: минорное обновление шелла не ломает загрузку конфига — только предупреждает.

## 6. Секреты

- Хранилище: **Secret Service** (gnome-keyring / KWallet) через `zbus`.
- В конфиге — только ссылка: `ai.providers.anthropic.api_key = { secret = "shell/anthropic"; }`.
- `shellctl config export --credentials omit` — выгрузка конфига без секретов (для багрепортов).
- Секреты не попадают ни в Nix store, ни в git, ни в `20-generated.nix`.

## 7. Что намеренно не конфиг

| Данные | Где |
|---|---|
| Состояние (свёрнутость панелей, история клипборда, последний запрос) | `~/.local/state/shell/state.json` |
| Секреты | Secret Service |
| Раскладка мониторов, хоткеи | конфиг композитора; шелл читает и **генерирует фрагменты** (см. `0003-compositor.md`) |

## 8. GUI настроек

- **Автоген форм** из JSON Schema для скалярных/enum/bool/числовых ключей: подпись, подсказка, валидация, «закреплено в Nix».
- **Ручные страницы** для визуального: раскладка бара (drag-and-drop зон), токены/тема, обои, профили.
- Индикаторы: источник значения (L1/L2/L3), «требуется перезапуск UI», «устаревший ключ».
- Кнопки: «применить», «отменить транзакцию», «сохранить в Nix» (commit).
